# mdtool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一个双击 `.md` 即在 ≤0.5s 内显示渲染结果、可 Ctrl+E 切换编辑的 Windows 单 exe 查看器。

**Architecture:** Rust（tao 窗口 + wry/WebView2）。文档在 Rust 中读取解码后经 initialization script 注入前端；前端资源嵌入 exe 并通过 `mdtool://` 自定义协议提供；渲染、编辑全在前端完成，保存/打开链接/关闭确认/外部修改经 IPC 与 Rust 交互。

**Tech Stack:** Rust 2021, wry 0.57, tao 0.37, include_dir, encoding_rs, winreg, windows-sys 0.61；前端 markdown-it 14、markdown-it-task-lists、markdown-it-footnote、markdown-it-texmath + KaTeX 0.16、highlight.js 11、CodeMirror 5.65。

Spec: `docs/superpowers/specs/2026-10-22-mdtool-design.md`

## File Map

| 文件 | 职责 |
|---|---|
| `src/doc.rs` | `Encoding` 枚举；`decode(&[u8]) -> Decoded`、`encode(&str, Encoding) -> Vec<u8>`、`load(&Path)`、`save(&Path, &str, Encoding)`、`mtime(&Path)`。纯逻辑，单测覆盖 |
| `src/protocol.rs` | `resolve(path: &str, doc_dir: &Path) -> Resolved`（App 资源 / Doc 本地文件 / NotFound）、`mime_for(&str)`、`handle(Request) -> Response` |
| `src/watch.rs` | `spawn(path, last_mtime: Arc<Mutex<Option<SystemTime>>>, proxy)` 轮询线程 |
| `src/win.rs` | `message_box(title, text, flags) -> i32`、`shell_open(target)`、`is_light_theme()`、`refresh_shell()` |
| `src/install.rs` | `install() -> Result<String>`、`uninstall() -> Result<()>` |
| `src/main.rs` | 参数解析、窗口、WebView、IPC 分发、事件循环、计时 |
| `assets/index.html` `assets/app.js` `assets/style.css` | 前端：渲染、懒加载、编辑模式、IPC |
| `assets/vendor/**` | 第三方库（下载的 min 版本） |
| `build.rs` `res/app.rc` `res/app.ico` `res/app.manifest` | 图标、DPI 感知 manifest |
| `sample.md` | 手测文档 |

IPC 协议（JS → Rust，`window.ipc.postMessage(JSON)`）：
- `{"cmd":"save","text":"...","close":bool}`
- `{"cmd":"dirty","value":bool}`
- `{"cmd":"open","url":"..."}`（http/https/mailto → 系统打开；其他视为相对文档目录的路径：`.md` 新进程打开，其他交给系统）
- `{"cmd":"rendered"}`（计时）

Rust → JS（`evaluate_script`）：
- `mdtool.onSaved(ok: bool, err: string)`
- `mdtool.onExternalChange(text: string)`
- `mdtool.requestSaveAndClose()`

### Task 1: doc.rs — 解码/编码/保存

**Files:** Create `src/doc.rs`; modify `src/main.rs`（`mod doc;`）

- [ ] Step 1: 写失败测试（在 `src/doc.rs` 的 `#[cfg(test)] mod tests`）：
  - `decode(b"# hi")` → `Encoding::Utf8`, text `"# hi"`, `lossy == false`
  - `decode(b"\xEF\xBB\xBF# hi")` → `Encoding::Utf8Bom`, text `"# hi"`
  - `decode(&[0xC4,0xE3,0xBA,0xC3])`（GBK「你好」）→ `Encoding::Gbk`, text `"你好"`
  - `decode(&[0xFF,0xFF,0xFF])` → `lossy == true`, `Encoding::Utf8`
  - `encode("你好", Gbk)` == 上面字节；`encode("x", Utf8Bom)` 以 BOM 开头
  - `save` 后 `load` 往返一致（临时目录 `std::env::temp_dir()`）
- [ ] Step 2: `cargo test doc` → 编译失败（函数不存在）
- [ ] Step 3: 实现。GBK 用 `encoding_rs::GBK.decode_without_bom_handling_and_without_replacement`，返回 None 即 lossy 回退 `String::from_utf8_lossy`
- [ ] Step 4: `cargo test doc` → 全部 PASS
- [ ] Step 5: commit `feat: document loading with encoding fallback`

### Task 2: protocol.rs — 路径解析与 MIME

**Files:** Create `src/protocol.rs`

- [ ] Step 1: 失败测试：
  - `resolve("/app/index.html", dir)` → `Resolved::App("index.html")`
  - `resolve("/doc/img/a%20b.png", dir)` → `Resolved::Doc(dir.join("img/a b.png"))`
  - `resolve("/doc/%E5%9B%BE.png", dir)` → `Resolved::Doc(dir.join("图.png"))`
  - `resolve("/other", dir)` → `Resolved::NotFound`
  - `mime_for("a.PNG") == "image/png"`，`mime_for("x.js") == "text/javascript"`，`mime_for("f.woff2") == "font/woff2"`，未知 → `application/octet-stream`
- [ ] Step 2: `cargo test protocol` → FAIL
- [ ] Step 3: 实现：自写百分号解码（按字节解码后 `String::from_utf8_lossy`）；`handle` 用 `include_dir!("$CARGO_MANIFEST_DIR/assets")` 取 App 资源，Doc 用 `std::fs::read`；App 资源加 `Cache-Control: no-store` 不需要（嵌入资源不变）
- [ ] Step 4: `cargo test protocol` → PASS
- [ ] Step 5: commit `feat: custom protocol path resolution`
